## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Post-sync backfill | Checking for missing assets AFTER the sync creates new rows causes false positives — assets just inserted with empty asset_url (download in flight) get double-queued | blocking | Call backfill as `asyncio.create_task` at the TOP of each sync, before any sync work |
| IS NULL only check | `asset_url IS NULL` misses 1135 real missing assets that have `asset_url = ''` | blocking | Always use `not a.asset_url` in Python or `(asset_url IS NULL OR asset_url = '')` in SQL |
| Rebuilding download logic | `_download_one` in assets.py already handles YouTube ID lookup, thumbnail download, video download, DB write-back, scoring reset, autofill trigger | advisory | Extract and reuse; do not reimplement |

**Task 3 — Create `backfill_missing_downloads_for_connection(connection_id, org_id, platform)` in `scheduler.py`**

This is the function the sync hooks will call. It:
1. Opens a DB session, queries missing creative_assets
2. If none found: returns silently (no BackgroundJob created)
3. Creates a BackgroundJob:
   ```python
   bg_job_id = await create_background_job(
       job_type="download",
       org_id=org_id,
       platform_connection_id=connection_id,
       metadata={"backfill": True, "asset_count": len(missing)},
       params={
           "platform": platform,
           "platform_connection_id": str(connection_id),
           "asset_ids": [str(a.ad_id) for a in missing],
       },
       initial_status="RUNNING",
       progress_total=len(missing),
   )
   ```
4. Dispatches `_run_download_backfill_job(bg_job_id, missing, connection)` as `asyncio.create_task`

The inner `_run_download_backfill_job` function:
```python
async def _run_download_backfill_job(bg_job_id, missing_assets, connection):
    from app.api.v1.endpoints.assets import _download_asset_for_backfill  # extracted in Task 1
    from app.services.sync.dv360_sync import DV360SyncService, _CookiesExpiredError
    dv360_svc = DV360SyncService() if connection.platform == "DV360" else None
    downloaded = []
    for i, asset in enumerate(missing_assets):
        try:
            ok = await _download_asset_for_backfill(asset, dv360_svc=dv360_svc)
            if ok:
                downloaded.append(str(asset.id))
        except _CookiesExpiredError:
            await update_background_job(bg_job_id, status="FAILED", progress_current=i,
                error={"type": "CookiesExpiredError", "message": "YouTube cookies expired", "traceback": ""})
            return
        except Exception as exc:
            logger.warning("download_backfill: asset %s failed: %s", asset.id, exc)
        await update_background_job(bg_job_id, progress_current=i + 1)
    await update_background_job(bg_job_id, status="COMPLETE",
        output={"downloaded_count": len(downloaded), "total": len(missing_assets)})
```

<decisions_made>

- **Pre-sync, not post-sync**: Backfill fires BEFORE sync work begins. Post-sync creates a race with the sync's own download queue — assets just created with empty asset_url (download in flight) would be double-queued. Pre-sync snapshot is clean.
- **Duplicate download is acceptable**: An asset appearing in both the backfill queue and the sync's own report will be downloaded twice at most. The write-back (`WHERE asset_url IS NULL OR asset_url = ''`) is idempotent — no data corruption, just wasted bandwidth. Rare in practice.
- **Reuse `_download_one`, don't use bulk functions**: The per-asset `_download_one` logic in `assets.py` does more than bulk functions — it also resets scoring status and triggers autofill. The bulk `_run_dv360_asset_downloads` only sets asset_url. For backfill we want the full reset behavior.
- **CDN thumbnails are "missing"**: `is_raw_cdn_url()` (YouTube img.youtube.com / ytimg.com) counts as missing because the decision was made to download and store all thumbnails in object storage. Legacy CDN URLs must be replaced.
- **New BackgroundJob per backfill run**: type=`download`, tracked the same as regular download jobs. Allows monitoring and retry via existing job infrastructure.
- **`run_initial_sync` excluded**: Brand new connection, no existing assets. Nothing to backfill.
- **Meta/TikTok included**: Add branches to `_download_asset_for_backfill` even though they're not the immediate priority. These platforms don't use YouTube video IDs — check their raw performance tables for download URLs.
- **Per-asset query in Python, not SQL**: `is_raw_cdn_url` is a Python function so we load all VIDEO assets for the connection and filter. Acceptable since connections have at most a few thousand assets.
</decisions_made>
