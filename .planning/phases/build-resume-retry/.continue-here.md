<decisions_made>

- INTERRUPTED = killed by system (Cloud Run SIGTERM/startup cleanup). PARTIAL = ran to completion but some items failed.
- Resume uses existing DB state (video_url on raw perf tables, AIInferenceTracking, CreativeScoreResult) — no per-item JSONB accumulation needed during execution
- DV360 exception: store `dv360_query_id` in output JSONB before poll loop (only checkpoint needed)
- 48h staleness check on DV360 query_id before resuming poll loop
- Retry always resumes from checkpoint (no "from scratch" option — adds complexity for no real use case)
- Retry creates a NEW job record (old one preserved for audit trail)
- Startup hook on FastAPI lifespan marks ALL RUNNING → INTERRUPTED (covers OOM/crash that SIGTERM can't catch)
- No heartbeat column, no APScheduler stale scanner (startup hook is sufficient)
- Meta/Google Ads/TikTok syncs: restart from scratch (idempotent upsert, no meaningful checkpoint)
- DV360 sync: resume poll loop with stored query_id (report already in flight on Google's side)
</decisions_made>
