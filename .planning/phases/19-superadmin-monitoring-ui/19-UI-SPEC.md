### 4. Status Filter Chips

Location: immediately below the tab header, inside each tab body before the job table.

Component: `MatChipsModule` (`mat-chip-listbox`, single-select).

Four chips:

| Label | Filter value | Selected state |
|-------|-------------|----------------|
| All | null (no filter) | accent border + accent text |
| Running | RUNNING | accent border + accent text |
| Completed | COMPLETE | accent border + accent text |
| Failed | FAILED | accent border + accent text |

Default selected: "All".

Filter applies client-side against the in-memory job map for the current tab's job_type. Does not trigger a new REST call.

Chip style (unselected): border 1px solid `var(--border)`, text `var(--text-secondary)`, background transparent, border-radius 20px, padding 4px 12px, font-size 13px.
Chip style (selected): border 1px solid `var(--accent)`, text `var(--accent)`, background `var(--accent-light)`.

### 6. Job List Table

One table per tab, rendered from the filtered+sorted in-memory job map.

Columns:

| Column | Width | Content |
|--------|-------|---------|
| Status | 90px | Status badge (see §Color status mapping) |
| Org | 160px | `org_id` short label (first 8 chars of UUID, monospace) |
| Started | 140px | `started_at` formatted as `MMM d, HH:mm` |
| Duration | 80px | Elapsed seconds if RUNNING, total seconds if ended; dash if PENDING |
| Progress | 180px | MatProgressBar (see below) |
| (click target) | flex-1 | Full row is clickable; cursor: pointer; hover: `var(--bg-hover)` |

Table style: matches `.admin-table` from admin.component.ts exactly:
- `width: 100%`
- `border-collapse: collapse`
- `thead` background: `var(--bg-hover)`
- `th, td` padding: 8px, text-align left, border-bottom: 1px solid `var(--border)`
- `th` font-size: 13px, weight 400, color `var(--text-secondary)`
- `td` font-size: 14px, color `var(--text-primary)`

Progress bar rules:
- Mode `determinate` when `progress_total > 0`, value = `(progress_current / progress_total) * 100`
- Mode `indeterminate` when status === RUNNING and progress_total === 0
- Hidden (not rendered) when status === COMPLETE or FAILED
- Label below bar: `{progress_current} / {progress_total}` in 11px `var(--text-muted)`; omitted when indeterminate

Pagination: "Showing 1–50 of N jobs" text below table, with Previous / Next mat-stroked-button buttons. Offset increments by 50. Font: 13px, `var(--text-secondary)`.

### 7. Action Buttons: Clear Completed / Clear Failed

Location: top-right of each tab, horizontally aligned with filter chips (flex row, `justify-content: space-between`).

Two buttons per tab:

| Button | Style | Enabled condition |
|--------|-------|-------------------|
| Clear completed | `mat-stroked-button`, accent border + accent text | At least 1 COMPLETE job visible in current tab type |
| Clear failed | `mat-stroked-button`, error border + error text | At least 1 FAILED job visible in current tab type |

Clear completed CSS: `border-color: var(--accent); color: var(--accent);`
Clear failed CSS: `border-color: var(--error); color: var(--error);`
Both: font-size 13px, height 32px.

Interaction: no modal confirmation — fire DELETE immediately, then show snackbar.

Post-delete snackbar (success):
- "N completed sync jobs cleared." (interpolate count + job_type)
- Duration: 3000ms, action: "Close"

Post-delete snackbar (error):
- "Failed to clear jobs. Check your connection and try again."
- Duration: no auto-dismiss, action: "Close"

Source: CONTEXT.md D-07, D-<specifics> snackbar note; admin.component.ts snackbar patterns.

## Accessibility Requirements

1. **Panel dialog**: `role="dialog"` + `aria-modal="true"` on `.slide-panel` (exact match of field-mappings-panel.component.ts line 107).
2. **Panel close button**: `aria-label="Close panel"` on the `mat-icon-button` (exact match of field-mappings-panel.component.ts line 129).
3. **Keyboard: Escape to close panel**: Component listens to `@HostListener('document:keydown.escape')` and emits `closed` when panel is open.
4. **SSE badge**: `aria-live="polite"` on the SSE status badge container so screen readers announce state changes without interrupting the user.
5. **Progress bar**: MatProgressBar provides `role="progressbar"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax` automatically in determinate mode. In indeterminate mode, `aria-label="Job in progress"` must be set explicitly on `<mat-progress-bar>`.
6. **Copy buttons**: `aria-label="Copy job ID"` and `aria-label="Copy traceback"` on icon-only or small button variants.
7. **Tab count badge**: `aria-label="N active jobs"` on the count badge span so the count is communicated to assistive tech.
8. **Filter chips**: `mat-chip-listbox` provides `role="listbox"` and `aria-selected` automatically.
9. **Table rows**: Clickable rows carry `role="button"` and `tabindex="0"` so keyboard users can trigger the detail panel with Enter/Space.
10. **External links**: Asset URL links in download drill-in carry `target="_blank"` + `rel="noopener noreferrer"` + `aria-label="Open asset in storage (opens in new tab)"`.

## Implementation Notes for Executor

1. **Do not modify `admin.component.ts`** — CONTEXT.md D decision. Job monitor is a completely separate route at `/configuration/jobs`.
2. **NgZone.run() is mandatory** — all SSE callback state updates must be wrapped in `NgZone.run()`. Failure to do this causes OnPush change detection to miss updates silently.
3. **OnPush change detection** — use `ChangeDetectionStrategy.OnPush` on all new components. Call `ChangeDetectorRef.markForCheck()` when BehaviorSubject emits (async pipe handles this automatically if used).
4. **CSS scoping** — all component-specific CSS goes into the component's `styles: []` array (inline), following existing project conventions. No new SCSS files unless the component warrants separation (job-detail-panel is complex enough to warrant a `.scss` file co-located in its subdirectory).
5. **Reuse `.admin-table` CSS** — copy the table style verbatim from admin.component.ts styles block rather than duplicating from styles.scss. The job list table is a peer of the admin tables.
6. **Reuse `.badge` global classes** — import from styles.scss; do not re-declare locally.
7. **`async` pipe preferred** — subscribe to `jobs$` and `connectionStatus$` via `async` pipe in templates to avoid manual subscription management on the list component (the service handles cleanup).
8. **Panel data fetch** — the panel component fetches `GET /api/v1/jobs/{id}` on each `job_id` input change (using `ngOnChanges`, same pattern as field-mappings-panel). Clears previous data before fetch to avoid stale display.
9. **Truncation logic** — apply `traceback.substring(0, 10240)` for display; store original in a separate property for clipboard write.
