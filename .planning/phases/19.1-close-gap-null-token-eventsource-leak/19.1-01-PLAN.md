The new connect() body must follow this EXACT ordering — ordering is a correctness constraint, not a style preference:

```typescript
  connect(): void {
    // BLOCKER-03: close any existing EventSource before opening a new one.
    // Must be FIRST so that a null-token early return still closes the old connection.
    this.eventSource?.close();

    // BLOCKER-02: guard against null token (token expiry, clearJobs reconnect, test bypass).
    const token = this.authService.getAccessToken();
    if (!token) {
      this.statusSubject.next('disconnected');
      return;
    }

    // Reset error budget so a fresh connect() does not inherit a prior session's onerror count.
    this.reconnectAttempts = 0;

    const url = `/api/v1/jobs/stream?token=${token}`;
    this.eventSource = new EventSource(url);

    this.eventSource.addEventListener('job_update', (event: MessageEvent) => {
      this.ngZone.run(() => {
        const job: JobSnapshot = JSON.parse(event.data);
        this.jobMap.set(job.job_id, job);
        this.jobsSubject.next(Array.from(this.jobMap.values()));
      });
    });

    this.eventSource.onopen = () => this.ngZone.run(() => {
      this.reconnectAttempts = 0;
      this.statusSubject.next('live');
    });

    this.eventSource.onerror = () => this.ngZone.run(() => {
      this.reconnectAttempts++;
      this.statusSubject.next(this.reconnectAttempts >= 3 ? 'disconnected' : 'reconnecting');
    });
  }
```

Key constraints:

- `const token = this.authService.getAccessToken()` is declared ONCE, at the top, after the close. The old `const token = ...` on the original line 39 is REMOVED (it is replaced by this declaration).
- `const url = ...` on the original line 40 is REMOVED (it is now inside the method after the guard, exactly as shown above).
- `this.reconnectAttempts = 0` appears AFTER the null guard and BEFORE `new EventSource(url)`.
- The addEventListener, onopen, and onerror handlers are identical to the originals — do not modify them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Angular service → EventSource URL | The JWT is embedded in the query string; a null token previously produced `?token=null`, which the backend correctly rejected with 401 but wasted a round trip and left the EventSource open |
| Browser EventSource → FastAPI SSE endpoint | Each EventSource holds a server-side pubsub subscription; an unclosed EventSource leaks that subscription until the server's disconnect-detection poll fires (~5 s) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19.1-01 | Information Disclosure | EventSource URL `?token=JWT` | accept | Token in query string is an existing architectural decision (EventSource cannot set headers); the fix does not change this — it prevents the token from ever being `null` in the URL |
| T-19.1-02 | Denial of Service | Leaked server-side pubsub subscriptions (BLOCKER-03) | mitigate | `this.eventSource?.close()` as first line of connect() ensures the old EventSource is closed before a new one opens, freeing the server-side subscription within ~5 s |
| T-19.1-03 | Denial of Service | Permanent 'disconnected' state after token-expiry onerror cycle (BLOCKER-02 extension) | mitigate | `this.reconnectAttempts = 0` reset at start of connect() ensures a fresh connect() starts with a full error budget rather than inheriting the prior session's count |
</threat_model>
