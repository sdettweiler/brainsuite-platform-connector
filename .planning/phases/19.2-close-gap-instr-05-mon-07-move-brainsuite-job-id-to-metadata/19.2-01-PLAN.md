<objective>
Close two partial gaps from the v1.3 milestone audit:

1. INSTR-05 partial — brainsuite_job_id for scoring jobs is stored in BackgroundJob.output but the References panel reads BackgroundJob.metadata_. New scoring jobs must write brainsuite_job_id into metadata_ after the BrainSuite API returns the job_id. The value stays in output too (backward compat).

2. MON-07 partial — platform_sync_run_id is listed in KNOWN_EXTERNAL_ID_KEYS (frontend) but is never set by any backend create_background_job() call. Removing it eliminates a permanently-empty References row.

Purpose: The job detail view References panel must display the BrainSuite job ID for scoring jobs so SuperAdmins can trace scoring runs end-to-end. This was the last unresolved display gap from Phase 17/19.

Output:
- job_tracker.py: update_background_job() gains an optional `metadata` parameter that merges the passed dict into the existing metadata_ JSONB (does not replace it).
- scoring_job.py: After the BrainSuite API returns job_id (around line 514), a new update_background_job() call stores brainsuite_job_id in metadata_.
- job-detail-panel.component.ts: KNOWN_EXTERNAL_ID_KEYS shrinks from 3 to 2 items (platform_sync_run_id removed).
- test_instrumentation.py: test_scoring_output_schema gains two assertions — that the metadata dict passed to create_background_job contains brainsuite_job_id, and/or that an update_background_job call merges it.
</objective>
