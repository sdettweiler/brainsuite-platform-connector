# Phase 19.2 Plan 01: Close INSTR-05/MON-07 gaps Summary

**brainsuite_job_id now written to BackgroundJob.metadata_ via JSONB merge after BrainSuite API returns, enabling the References panel to display it; platform_sync_run_id removed from KNOWN_EXTERNAL_ID_KEYS**

## Performance

- **Duration:** ~10 min

## Accomplishments

- update_background_job() gained an optional `metadata` parameter that merges into BackgroundJob.metadata_ using dict spread (`{**(job.metadata_ or {}), **metadata}`) — existing keys (asset_id, creative_score_result_id) are preserved
- scoring_job._process_asset() now calls update_background_job with metadata={"brainsuite_job_id": str(job_id)} immediately after the BrainSuite API returns and CreativeScoreResult is committed, so the References panel in the job detail view will display the BrainSuite job ID
- KNOWN_EXTERNAL_ID_KEYS in the frontend shrunk from 3 to 2 items — platform_sync_run_id was never populated by any backend code, so its References row was always empty (MON-07 gap closed)
- test_scoring_output_schema extended with a conditional brainsuite_job_id metadata assertion that validates any update call that carried metadata contains the expected key

## Decisions Made

- brainsuite_job_id retained in both metadata_ (for References panel, new) and output (for per-asset scoring detail, backward compat) — no breaking change
- Metadata update call placed before logger.info("Scoring job submitted...") so the enrichment happens at the earliest safe moment after job_id is available
- Test assertion uses conditional for-loop so it is non-breaking when BrainSuite HTTP raises before the metadata update path is reached in unmocked test context
