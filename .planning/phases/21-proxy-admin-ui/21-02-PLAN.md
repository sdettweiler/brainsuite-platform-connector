<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM ↔ component state | User input in the URL `<input>` is bound via `[(ngModel)]`; never written to the DOM as raw HTML |
| Browser ↔ backend API | HTTPS-authenticated SuperAdmin requests; CSRF protected by existing auth interceptor |
| Component → SnackBar | Toast strings are static literals from the UI-SPEC Copywriting Contract; never interpolate user-controlled strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-08 | Information Disclosure | DOM after URL save | mitigate | Component never stores the raw `newProxyUrl` past `savePoxyUrl` success — set `this.newProxyUrl = ''` on completion. Template only renders `proxyConfig.proxy_url_masked` (already masked by backend per Plan 21-01). |
| T-21-09 | Tampering | URL input | mitigate | `[(ngModel)]` binds the input through Angular's value sanitizer; the value is sent verbatim in the PUT body — backend validates at encryption time and rejects malformed URLs is out-of-scope for this phase (deferred per RESEARCH.md Open Question 1). Frontend trims whitespace before send (`this.newProxyUrl.trim()`). |
| T-21-10 | Elevation of Privilege | Navigation to /configuration/admin | accept | Route guard for SuperAdmin is enforced upstream; not introduced or weakened by this phase. Backend endpoints in Plan 21-01 enforce `get_current_superadmin` server-side — the UI being visible to a non-superadmin user-agent never produces successful API calls (403 returned). |
| T-21-11 | Information Disclosure | Test result `error` text rendered in DOM | mitigate | Backend returns short error strings (`"Connection timed out after 5s"`, `"HTTP <code>"`, or sanitized exception message — see Plan 21-01 T-21-06). The frontend renders error via Angular interpolation (`{{ testResult.error }}`), which auto-escapes HTML; no `innerHTML` binding. |
| T-21-12 | Spoofing | Snackbar success after silent network failure | mitigate | All four `.subscribe({ next, error })` handlers route errors into a separate snackbar with explicit failure copy; only the success branch shows a positive snackbar — see Pitfall 1 in RESEARCH.md. |

**Residual risk:** Low. The frontend never has access to plaintext credentials; all sensitive handling lives in Plan 21-01 backend.

**No package legitimacy gate required:** Zero new npm packages are added (per UI-SPEC §Registry Safety).
</threat_model>
