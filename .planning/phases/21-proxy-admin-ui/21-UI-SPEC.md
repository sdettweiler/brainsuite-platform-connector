## Layout — Card Structure

The Residential Proxy card is Section 1 in `admin.component.ts`, inserted before the existing YouTube Cookies `<section>`. It reuses the `.config-section` / `.section-header` / `.section-body` / `.cookie-card` CSS classes verbatim — no new layout classes are needed.

```
<section class="config-section">
  <div class="section-header">
    <h2>Residential Proxy</h2>
    <p class="section-desc">...</p>
    [toggle row — right-aligned, matches .scoring-toggle-row]
  </div>
  <div class="section-body">
    <div class="cookie-card">
      [URL area — 4 states]
    </div>
    [Test Connection row]
    [Inline test result — optional]
  </div>
</section>
```

The toggle is placed in the `.section-header` (right side), mirroring the Scoring Controls pattern where label + hint sit left and the `MatSlideToggle` sits right. The section body contains only the URL sub-card and the Test Connection row.

## Interaction States

### URL Area — 4 States

| State | Trigger | Display |
|-------|---------|---------|
| **Loading** | `loadingProxy = true` | `.skeleton-block` (height 56px, matches existing skeleton pattern) |
| **No URL** | `proxyConfig.proxy_url_masked === null && !editingProxyUrl` | `.cookie-missing`: "No URL saved." (`.text-muted`) + "Add URL" stroked button |
| **URL configured** | `proxyConfig.proxy_url_masked !== null && !editingProxyUrl` | `.cookie-display`: masked string in `.masked` (monospace) + "Replace" stroked button. Entire `.cookie-card` has `opacity: 0.5` and pointer-events: none when `proxy_enabled = false` (signals URL irrelevant while disabled) |
| **Edit mode** | `editingProxyUrl = true` | Single-line `<input>` (not textarea) with `placeholder="http://user:pass@host:port"`, `.cookie-edit-actions` row: "Discard" (stroked) + "Save URL" (filled accent) |

### Toggle

- Toggle label: "Enabled" when checked, "Disabled" when unchecked — matches Scoring Controls label pattern exactly.
- Hint text: "Routes all YouTube downloads through the configured residential proxy."
- While `togglingProxy = true`: toggle is `[disabled]="true"`.
- On success: snackbar "Proxy enabled." or "Proxy disabled." (duration 3000ms).
- On error: snackbar "Failed to update proxy toggle." (no auto-dismiss).

### Test Connection Button

- Disabled when: `!proxyConfig?.proxy_enabled || !proxyConfig?.proxy_url_masked || testingProxy`
- Label: "Test Connection" (idle) / spinner + "Testing…" (while `testingProxy = true`)
- Placed below the `.cookie-card` in `.section-body`, left-aligned, `mat-stroked-button`
- After result: inline result text appears below the button with `margin-top: 8px`

### Test Result Inline

- Pass: `<span style="color: var(--success); font-size: 13px;">Reachable ({{ testResult.latency_ms }}ms)</span>`
- Fail: `<span style="color: var(--error); font-size: 13px;">Failed: {{ testResult.error }}</span>`
- Result persists for the session (no auto-clear). A new test run overwrites the previous result.
- Cleared on component destroy and when proxy is disabled (result is irrelevant without an active proxy).

## Accessibility

- Toggle: `aria-label="Residential proxy"` on `<mat-slide-toggle>` (MatSlideToggle renders role="switch" automatically).
- URL input: `aria-label="Proxy URL"` when shown in edit mode.
- Test Connection button: `aria-disabled="true"` propagated by `[disabled]` binding on mat-stroked-button.
- Inline test result: `role="status"` on the container `<div>` so screen readers announce updates without focus shift.
- Masked URL: wrap in `<span aria-label="Proxy URL configured, masked">` so screen readers do not read out bullet characters.
