  <action>
    Bring up the dev stack and run the seven verification steps below in a real browser. This task is a blocking human checkpoint — the executor's job is to (1) ensure the dev stack is reachable, (2) print the verification script for the developer, and (3) record the developer's approval or failure list. The executor does NOT decide whether the phase passes; the developer does.

    Pre-flight (executor runs):
    1. Run `docker-compose ps` to confirm the dev stack is running. If not, run `docker-compose up -d` (hyphenated CLI per memory `feedback_docker_compose.md` — never `docker compose`). Do NOT run `down -v` or any other volume-destructive command (per memory `feedback_never_destroy_volumes.md`).
    2. Confirm backend health: `curl -sf http://localhost:8000/api/v1/health` returns 200 (or the project's equivalent health endpoint — check `docker-compose.yml`).
    3. Confirm the frontend URL: cat `docker-compose.yml` to find the frontend port mapping (likely 4200 or 80); use that for the developer's browser steps.

    Verification steps (developer runs in browser; executor relays results):

    Step A1 — Card visible (SC-1):
    - Sign in as a SuperAdmin user and navigate to `/configuration/admin`.
    - Confirm a card with `<h2>Residential Proxy</h2>` is rendered.
    - Confirm it is the FIRST `.config-section` on the page (above YouTube Cookies). Use browser inspector: the YouTube Cookies `<h2>` must appear LATER in DOM order than the Residential Proxy `<h2>`.
    - Confirm the toggle, the URL area, and the section description "Manage the system-wide residential proxy used for YouTube video creative downloads on production hosts." are visible.

    Step A2 — URL save and masking (SC-2):
    - Toggle the proxy ON.
    - Click "Add URL" (or "Replace" if a URL is already saved), enter a fake URL `http://uatuser:uatpass@geo.iproyal.com:12321`, click "Save URL".
    - Confirm a snackbar "Proxy URL saved." appears.
    - Confirm the masked display shows exactly `http://••••••@geo.iproyal.com:12321` (six bullets between `http://` and `@`).
    - Open DevTools → Network → refresh the page → click the GET request to `/api/v1/super-admin/proxy-config` → inspect Response body. Assert: contains key `proxy_url_masked` with bullet form; contains NO key `proxy_url`; contains no substring `uatuser` and no substring `uatpass`.

    Step A3 — Toggle off greys URL, persistence (SC-3):
    - Toggle proxy OFF. Confirm: (a) snackbar "Proxy disabled." appears, (b) `.proxy-url-card` becomes visually greyed (opacity ~0.5), (c) Test Connection row disappears.
    - Refresh page. Toggle state must remain OFF (D-01 immediate save).
    - Toggle ON, refresh; state stays ON.

    Step A5 — Mask format (D-04):
    - With URL saved, visible string must match `^https?://••••••@.+:\d+$`.

    Step A6 — Test Connection (D-07, D-08, D-09):
    - Proxy ON, URL saved → click "Test Connection".
    - Within ~6 seconds, either green "Reachable (NNNms)" or red "Failed: …" appears inline below the button. With a fake URL the result will be Failed — that is OK provided the rendering is correct.
    - Button text reverts from "Testing..." to "Test Connection" after result.
    - Disable proxy → Test Connection row disappears.

    Step A7 — Section order (D-10):
    - In DOM, `<h2>Residential Proxy</h2>` line comes BEFORE `<h2>YouTube Cookies</h2>`.

    Step A4 — Non-superadmin invisibility (SC-4):
    - Incognito window → sign in as a NON-SuperAdmin user (regular tenant user from dev DB).
    - Navigate to `/configuration/admin`.
    - Pass condition: route is blocked (redirect / 403) OR the page renders but the Residential Proxy `<section>` is absent from DOM AND the GET `/api/v1/super-admin/proxy-config` returns 403 in the Network tab.
    - Fail condition: non-SuperAdmin sees the Residential Proxy card OR sees a plaintext URL anywhere.

    On developer "approved": close phase 21, mark all 3 plans complete, advance roadmap.
    On developer "issues" or numbered failures: trigger `/gsd-plan-phase 21 --gaps` with the failed A-IDs as inputs. Do NOT auto-approve, do NOT silence failures.
