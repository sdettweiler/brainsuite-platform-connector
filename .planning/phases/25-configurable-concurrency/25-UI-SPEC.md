spacing values are introduced in Phase 25 — all measurements re-use established tokens.

| Token | Value | Usage in This Phase |

  utility already in global styles

## Layout Contract

### Section restructure

The existing two standalone top-level sections ("Residential Proxy" and "YouTube Cookies") are
merged into one top-level `<section class="config-section">` called **"Download Settings"**.
The three subsections inside are separated by visual dividers using the existing
`border-top: 1px solid var(--border)` pattern.

```
<section class="config-section">  <!-- "Download Settings" -->
  <div class="section-header">
    <h2>Download Settings</h2>
    <p class="section-desc">Configure parallel download concurrency, residential proxy, and YouTube cookies.</p>
  </div>
  <div class="section-body">
    <!-- Subsection 1: Parallel Downloads (new, positioned FIRST) -->
    <div class="subsection">
      ...slider UI...
    </div>
    <!-- Visual divider -->
    <hr class="subsection-divider"> OR <mat-divider>
    <!-- Subsection 2: Residential Proxy (moved) -->
    <div class="subsection">
      ...existing proxy toggle + URL card + test...
    </div>
    <!-- Visual divider -->
    <hr class="subsection-divider"> OR <mat-divider>
    <!-- Subsection 3: Cookies (moved) -->
    <div class="subsection">
      ...existing cookie cards...
    </div>
  </div>
</section>
```

Existing standalone "Residential Proxy" and "YouTube Cookies" `<section>` elements are
**removed** and their content migrated into the subsections above.

### Parallel Downloads subsection layout

```
[ Subsection label: "Parallel Downloads"       ] ← 14px/600
[ Hint: "Set the max number of..." 13px/muted  ]
                                                  ← 16px gap
[ slider ←——●——————————→ ] [ 3 ]                  ← track + numeric readout
                                                  ← 8px gap
[ range labels: 1 ——————————————— 10           ]  ← optional, 12px/muted
                                                  ← 12px gap
[                    [Discard]  [Save]         ]  ← right-aligned
```

## Interaction Contract

### mat-slider: Parallel Downloads

| Property | Value | Source |
|----------|-------|--------|
| Component | `<mat-slider discrete>` | CONTEXT.md D-09 |
| `min` | 1 | REQUIREMENTS.md PERF-02 |
| `max` | 10 | REQUIREMENTS.md PERF-02 |
| `step` | 1 | CONTEXT.md D-09 |
| Thumb label | shows current integer value | discrete mode built-in behavior |
| Default displayed value | 3 | CONTEXT.md D-11; server_default on DB column |
| On slide | updates `concurrencyDraft` local variable only; does NOT auto-save | CONTEXT.md D-10 |
| On Save click | `PUT /api/v1/super-admin/download-concurrency` with `{ max_concurrent_downloads: N }` | CONTEXT.md D-13 |
| On Discard click | resets `concurrencyDraft` to last saved `concurrencyConfig.max_concurrent_downloads` | CONTEXT.md D-10 |
| While saving | Save button disabled + shows `mat-spinner diameter=14` + label "Saving..." | matches proxy URL save pattern |
| Save success | snackBar: "Concurrency setting saved." duration 3000ms | matches existing snackBar patterns |
| Save error | snackBar: "Failed to save concurrency setting. Check your connection and try again." | matches proxy URL error pattern |
| Load error | snackBar: "Could not load concurrency config. Refresh to retry." | matches proxy load error pattern |

### Save / Discard button states

| State | Save button | Discard button |
|-------|-------------|----------------|
| Idle (value unchanged from saved) | enabled, `mat-flat-button save-btn` | enabled, `mat-stroked-button` |
| Idle (value changed from saved) | enabled, `mat-flat-button save-btn` | enabled, `mat-stroked-button` |
| Saving | disabled, spinner + "Saving..." | disabled |
| Loading initial data | both disabled (skeleton shown instead) | both disabled |

Note: Phase 25 does not implement "dirty" state detection (no visual diff indicator between
current vs. saved value). This matches the existing proxy URL pattern — Discard simply resets
to the last fetched server value. The user always has explicit Save/Discard control.

## CSS Contract

New CSS rules to add inside the `styles: []` array in `admin.component.ts`. All new rules
follow the existing BEM-like flat class naming convention in the component.

```scss
/* Subsection within merged Download Settings section */
.subsection {
  border-top: 1px solid var(--border);
  padding-top: 16px;
  margin-top: 16px;
}
.subsection:first-child {
  border-top: none;
  padding-top: 0;
  margin-top: 0;
}

/* Subsection heading row (label + hint) */
.subsection-label { font-weight: 600; font-size: 14px; margin-bottom: 4px; }
.subsection-hint  { font-size: 13px; color: var(--text-secondary); max-width: 480px; margin-bottom: 16px; }

/* Slider row: track + numeric readout */
.slider-row {
  display: flex;
  align-items: center;
  gap: 12px;
  margin-top: 8px;
}
.slider-value {
  font-weight: 600;
  font-size: 14px;
  min-width: 20px;
  text-align: right;
  color: var(--text-primary);
}

/* Save/Discard action row */
.slider-actions {
  display: flex;
  gap: 8px;
  justify-content: flex-end;
  margin-top: 12px;
}
```

The existing `.save-btn` class (accent background, white text, inline-flex, gap-8px) is
reused as-is for the Save button. No new button variants needed.
