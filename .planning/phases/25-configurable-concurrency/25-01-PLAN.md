    Define `async def get_concurrency_semaphore() -> asyncio.Semaphore` with this exact behavior:
    1. Acquire `_cache_lock` for the entire function body via `async with _cache_lock:`.
    2. If `time.monotonic() < _concurrency_cache["expires_at"]`, return `_concurrency_cache["semaphore"]` (cache hit — no DB).
    3. On cache miss:
       a. Default `max_concurrent = 3`.

Capacity-change detection (D-03): if `max_concurrent != _concurrency_cache["max_concurrent"]`, create a new `asyncio.Semaphore(max_concurrent)` and store it; otherwise reuse the existing semaphore object. This preserves the in-flight-finishes-on-old-semaphore property because callers that already acquired the prior Semaphore reference keep using it.
    5. Update `_concurrency_cache["max_concurrent"]`, then set `_concurrency_cache["expires_at"] = time.monotonic() + CACHE_TTL_SECONDS`.
    6. Return `_concurrency_cache["semaphore"]`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB ↔ application memory | SystemConfig row is the source of truth for max_concurrent_downloads; loaded into `_concurrency_cache` on cache miss |
| TTL boundary | After CACHE_TTL_SECONDS, cached capacity is treated as stale; new value MUST be re-loaded before being trusted |

No external trust boundary is crossed in this plan — no user input touches the column, no credential is involved, no API surface is added (that lands in Plan 25-02).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Denial of Service | `get_concurrency_semaphore` DB read on cache miss | mitigate | Use `async with get_session_factory()() as db:` context manager so the DB session is closed BEFORE the function returns the Semaphore (per RESEARCH.md Pitfall 2). Callers never hold a DB session across `async with semaphore:`. |
| T-25-02 | Denial of Service | Race on first cache miss with N concurrent callers | mitigate | Single shared `_cache_lock` (already in proxy_cache.py) wraps the entire read-or-load body — serializes all first-callers to a single DB query. Tested in `test_concurrency_semaphore_concurrent_first_callers_serialize`. |
| T-25-03 | Tampering | DB column receives invalid value (negative / huge) directly via SQL | accept | Defense lives at the Pydantic API boundary in Plan 25-02 (Field(ge=1, le=10)). At the storage layer we accept any Integer per D-12 (no CHECK constraint). Direct SQL writes are SuperAdmin-only attack surface; out-of-range value would cause asyncio.Semaphore(negative) to ValueError on cache load — caught by the broad `except Exception` block and falls back to default 3. |
| T-25-04 | Information Disclosure | Logging the concurrency value | accept | The value is non-sensitive (it is a tuning integer, not a credential). The warning format string `"Failed to load concurrency config from DB: %s"` formats only the exception, not the value. |
| T-25-05 | Denial of Service | Alembic migration applied to a populated database fails | mitigate | `server_default="3"` ensures existing rows receive the value during ADD COLUMN; `nullable=False` is safe because the server default is applied at backfill time. Downgrade drops the column cleanly. Reachable via `alembic downgrade -1` in Phase 26 work. |

No high-severity threats remain after mitigations; ASVS L1 gate passes.
</threat_model>
