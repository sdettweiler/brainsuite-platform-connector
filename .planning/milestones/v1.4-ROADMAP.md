## Milestone Summary

**Known Gaps:**
- PROXY-02: Google Ads live download validation was blocked by pre-existing environment issues (MCC manager accounts rejecting metric queries; `youtube_cookies_runtime_expired` flag from prior rate-limit event). Code path is identical to DV360 (which validated). Not a code deficiency — acknowledged gap.

**Key Decisions:**
- Three-layer proxy stack (all required): residential IP → cookies → bgutil PO token plugin
- Both DV360 and Google Ads use the same yt-dlp proxy path — fixed together per "fix all platforms simultaneously" rule
- bgutil sidecar runs in HTTP server mode (port 4416) — Script mode causes cold-start latency + orphan processes
- Metadata filter JOIN always includes org_id guard — omitting exposes cross-org data (T-22-01 security requirement)
- `null_duration_count` gated on filter activity — avoids expensive COUNT on every dashboard page load
- Alembic DEBT-01 (multi-head) deliberately preserved — `alembic upgrade e8f9a0b1c2d3`/`a9b0c1d2e3f4` specific commands documented; head merge deferred to v1.5

**Issues Resolved:**
- httpx proxies= kwarg TypeError (BLOCKER-01 from v1.4 audit) fixed before milestone close
- mat-menu teardown on click (ng-template else-branch + memoized getter)
- Duration slider bounds reset on filter change; single-value range edge case
- Phase 20 bgutil: rate-limit DV360 entity API fix + bgutil sidecar install fix (post-execution)

**Issues Deferred:**
