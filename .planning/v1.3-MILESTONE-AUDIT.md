## Integration Blockers

### BLOCKER-01: TikTok download manifest false-positive
**Affects:** INSTR-02, MON-04

`enrich_creatives_deferred()` in `tiktok_sync.py` catches all exceptions silently, never raising and never returning a result. The caller in `scheduler.py` unconditionally adds every `ad_id` to the `downloaded` list and never populates the manifest URL. Result: the download drill-in panel always shows 100% success with no storage links, regardless of actual outcomes.

**Fix:** `enrich_creatives_deferred` must propagate errors (re-raise or return `(success, url)` tuple). The caller must route to `downloaded` vs `failed` and capture the resolved S3 URL for the manifest entry.

### BLOCKER-02: Null token race on SSE connect
**Affects:** SSE-01, MON-01, MON-02

`job-monitor.service.ts` `connect()` calls `this.authService.getAccessToken()` which can return `null` before token hydration. No null-guard before building the URL produces `?token=null`; backend returns 401; `reconnectAttempts` increments indefinitely with no reset on successful reconnect.

**Fix (2 lines):**
```typescript
const token = this.authService.getAccessToken();
if (!token) { this.statusSubject.next('disconnected'); return; }
```

### BLOCKER-03: EventSource leak on clearJobs
**Affects:** SSE-01, SSE-02, MON-01

`connect()` opens a new `EventSource` without closing the existing one. `JobMonitorComponent.clearJobs()` calls `connect()` without calling `disconnect()` first. Each clear action leaks a live server-side pubsub subscription.

**Fix (1 line at start of `connect()`):**
```typescript
this.eventSource?.close();
```

## Integration Warnings

### WARNING-01: brainsuite_job_id missing from References panel (MON-07 partial)
`scoring_job.py` stores `brainsuite_job_id` in the `output` dict, not `metadata_`. `getExternalIds()` in the detail panel reads only `metadata_` → BrainSuite external job ID never shown in scoring job drill-ins.

**Fix:** Either move `brainsuite_job_id` into `metadata_` in `scoring_job.py:405`, or extend `getExternalIds()` to also check `output` for known external ID keys.

### WARNING-02: TikTok download manifest URL always empty (MON-04 degraded)
Even when TikTok asset downloads succeed, the manifest `url` field is always `""` — no "Open in storage" link appears. The S3 URL is stored in `CreativeAsset.asset_url` but never piped back into the job output manifest.

**Fix:** Either fix BLOCKER-01 (return the URL from `enrich_creatives_deferred`) or extend the `get_job` endpoint enrichment to back-fill `url` from `CreativeAsset.asset_url` for TikTok download manifest entries.

### WARNING-03: TikTok download ignores scoring_enabled toggle
All 4 `_run_tiktok_creatives_deferred` call sites in `scheduler.py` (lines 301, 1034, 1385, 1702) fire unconditionally after harmonization, regardless of `SystemConfig.scoring_enabled`. TikTok assets are always downloaded even when auto-scoring is disabled.

**Fix:** Add `scoring_enabled` guard at the 4 call sites, consistent with the existing `run_scoring_batch()` gate check.

### WARNING-04: DELETE /api/v1/jobs accepts RUNNING/PENDING (CR-03)
No server-side guard prevents deleting active jobs. Direct API callers can delete RUNNING rows while orchestrators still hold the job ID, causing silent orphaned `update_background_job` calls.

### WARNING-05: sse-starlette version is correctly 1.8.2 (non-issue)
VERIFICATION.md Phase 18 reported a discrepancy; integration checker confirmed `requirements.txt` correctly has `sse-starlette==1.8.2`. This is resolved — no action needed.
